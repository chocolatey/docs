## Summary

This document explains how to install and use Chocolatey, one of the simplest, most powerful package managers for Windows. If you're not quite sure what Chocolatey is or what it does, the first question to ask is <Xref title="Why Chocolatey?" value="why" />

If you're already familiar with Chocolatey, great! We're glad you're here; let's get started!

## Requirements

Check our list of <Xref title="Supported Windows Versions" value="chocolatey-products-dependencies-and-support-lifecycle" anchor="supported-windows-versions" /> to ensure compatibility.

While Chocolatey is compatible with PowerShell v2+, these installation instructions require Powershell v3+ due to a [TLS 1.2 requirement](https://blog.chocolatey.org/2020/01/remove-support-for-old-tls-versions/). We also require .NET Framework 4.8, and we'll attempt to install it on your machine if it's not already installed.

## Using Chocolatey

Now that you have Chocolatey on your machine, let's look at the three most commonly used commands; shown as examples below.

First, let's <Xref title="install" value="choco-command-install" /> [Notepad++](https://notepad-plus-plus.org/).

1. Open PowerShell as an administrator.
1. Type `choco install notepadplusplus -y` and press Enter.
1. That's it. A simple yet powerful concept!

Upgrading is a similar process; instead of the install command, we'll use the <Xref title="upgrade" value="choco-command-upgrade" /> command.

1. Open PowerShell as an administrator.
1. Type `choco upgrade notepadplusplus -y` and press Enter.
1. If there's an upgrade available, Chocolatey will upgrade the package. If there isn't, Chocolatey lets you know you have the latest package version available!

Uninstalling is just as easy. Let's <Xref title="uninstall" value="choco-command-uninstall" /> Notepad++.

1. Open PowerShell as an administrator.
1. Type `choco uninstall notepadplusplus -y` and press Enter.
1. You're done!

## Terminology

Software and Package are not terms used interchangeably in the Chocolatey community. It's important to understand the distinction between them and how they are related.

* **Chocolatey** - A Windows package manager for software management. It can also be considered a framework.
* **Chocolatey.org** - The one-stop website for Chocolatey information. It is important to understand that Chocolatey and the [Chocolatey Community Repository](https://community.chocolatey.org) are not intertwined, they are not the same thing. See <Xref title="community feed disclaimer" value="community-packages-disclaimer" /> to get a better understanding.
* **NuGet** - Framework and .NET package manager for software libraries. Chocolatey uses the NuGet packaging framework.
* **Package** - See [What are Chocolatey Packages?](#what-are-chocolatey-packages) Packages may contain the software they represent and the final location of software may or may not be in the package. Packages may also contain scripts or files.
* **Software** - Software refers to the actual runtime software that a package represents. This can be installed to the system through native installers, come from zip/archive files, or dropping the runtime software right into the package.
* **Native Installer** - Actual installers that install software into Programs and Features "natively" on a Windows machine. Examples include MSI, InnoSetup (exe), NSIS (exe), InstallShield (exe/msi), etc. Windows has over 20 different installer formats.
* **Install Package** - Packages that wrap (include) native installers.
* **Portable Package** - Packages that use zip or just contain the runtime software. Usually these packages do not require administrative privileges to install or run. See <Xref title="Portable application" value="faqs" anchor="portable-application-something-that-doesnt-require-a-system-install-to-use" />
* **Extension Package** - Packages that provide extensions to Chocolatey's PowerShell module through additional PowerShell modules.
* **Template Package** - Packages that have packaging templates in them, used in package creation. See <Xref title="create your own package templates" value="create-custom-package-templates" />.
* **Metapackage** - Packages that only exist to take dependencies on other packages, usually as a way of providing one command to get a complete setup. Some metapackages exist to provide discoverability, such as "git" versus 'git.install." The git package just depends on git.install, so running the install for either package will result in the git software being installed on the machine.
* **Virtual package** (_not yet implemented_) - a concept that a package can "provide" some functionality and any package that meets that provides will be considered a dependency met. For example, if you need to take a dependency on a pdf reader, you wouldn't want to take a hard dependency on AdobeReader, but instead you would hope that adobereader provides pdf as well as other packages like SumatraPDF and FoxitReader. Then you could take a dependency on pdf and if any of those packages are installed, the dependency is met. Otherwise an algorithm would determine which one to install.
